# 054 - Starlark Inside BUILD Files

**Concepts:** comprehensions, string formatting, load-time `if`

## Run it

```bash
bazel query //054_starlark_in_build:all
bazel build //054_starlark_in_build:all_configs
cat bazel-bin/054_starlark_in_build/auth.conf
```

Three `genrule` targets exist, generated by one comprehension.

## The comprehension pattern

```python
SERVICES = ["auth", "billing", "search"]

[
    genrule(name = "%s_config" % s, ...)
    for s in SERVICES
]
```

Adding a service is a one-word edit. This scales well and is extremely common
in real repos - especially for generating a test target per input file.

## What Starlark is missing

Starlark is Python-*like*, deliberately restricted so builds stay
deterministic and analyzable:

- No `import` (only `load()`)
- No classes, no `while`, no recursion
- No file I/O, no `os`, no network
- No global mutable state; values are frozen after their file is loaded
- `+` on lists works, but mutating a list you received is forbidden

These restrictions are what let Bazel cache the result of loading a package.

## `if` STATEMENTS ARE ILLEGAL IN BUILD FILES

This is a rule people hit constantly:

```python
if SOMETHING:        # ERROR: `if` statements are not allowed in BUILD files
    genrule(...)
```

`if` **statements** are allowed only inside functions in `.bzl` files. In a
BUILD file you have two legal options:

```python
# 1. An `if` EXPRESSION (ternary) - this is an expression, so it is fine:
TAGS = ["experimental"] if INCLUDE_EXPERIMENTAL else ["stable"]

# 2. A comprehension over a conditionally-empty list, to make a target optional:
[
    genrule(name = "experimental", ...)
    for _ in ([1] if INCLUDE_EXPERIMENTAL else [])
]
```

The restriction exists to keep BUILD files declarative and cheaply analyzable.
If the logic is complex enough to want a real `if`, it belongs in a macro.

## Load-time conditionals are not `select()`

```python
TAGS = [...] if FLAG else [...]   # decided when the BUILD file is READ
srcs = select({...})              # decided per BUILD CONFIGURATION (sample 056)
```

An `if` on a Starlark constant produces a different *graph*. A `select()`
produces one graph whose attribute values vary by configuration. If you find
yourself wanting `if` on something that changes per platform, you want
`select()`.

## Know when to stop

A BUILD file with nested comprehensions and helper functions is hard to read
and impossible to grep. Once logic grows past a comprehension or two, move it
into a macro in a `.bzl` file (sample 051).

## Key takeaway

Comprehensions for repetition, `.bzl` macros for logic, `select()` for
configuration.
